# Ark ID

`.ark` names from the existing BNS service, surfaced in the app for the first
time. Frontend only: no BNS, Kash, gateway or contract change.
See `docs/adr/ADR-2026-09-26-ark-id-and-usdc-payment.md`.

## What a holder gets

- **A card in the sidebar**, above the account button. It shows the verified
  name the wallet owns, or the claim promo when it owns none.
- **A sheet** to search a label, see its price, register it, and renew it.
  Labels are lower-cased and `.ark` is appended exactly once.
- **Their name on the Kash card**, copyable, once the reverse record is
  verified against the wallet.
- **Kash send to a name.** An Ark ID is accepted anywhere an address is, and
  resolves through BNS; an unresolvable name is an error state with a link to
  buy one. Direct addresses behave exactly as before.

## Priced in USDC, paid in USDC

The BNS registrar is payable in native Base ETH. Customers are shown one
currency: the price is converted at the live ETH/USD rate, and one action
quotes a Base-USDC-to-native-ETH route through the existing Dextopus
integration, sends the exact quote, waits for terminal settlement and verifies
the wallet balance, then sends the payable registration transaction.

The copy never names Dextopus or native ETH. The wallet's own final
confirmation still shows ETH, because that is the contract's unit.

## Registration is commit and reveal

The commitment response carries **the only copy of the reveal secret**, so the
whole tuple is persisted in browser storage keyed by wallet and label, and
removed once registration completes or expires. It is never sent to a backend.
The modal holds a blocking progress state through payment and keeps the
Dextopus request id, so a reload resumes rather than losing a paid-for name.

## Kash send is still hidden

The send-to-an-Ark-ID path lands behind `KASH_SEND_ENABLED`, which is `false`
since 2026-09-26. The modal work is complete and dormant; it becomes reachable
when Send is restored. The Ark ID on the Kash card is not gated and shows now.

## The proxy

`app/api/bns/[...path]` is a same-origin proxy with a narrow endpoint
allowlist. Writes go through the existing request-session verification, and BNS
remains the source of all transaction calldata and chain validation.

## Bundle

The sidebar is in the shell on every route, so the Ark ID modal — which pulls
viem and the send/deposit hooks — is loaded with `next/dynamic`, as every modal
in `app-modals.tsx` is. Imported statically it put all of that in the initial
payload of the whole app and took ten routes over their first-load budget. No
budget was raised.

## Verification

`./scripts/preflight.sh` clean, and first-load budgets pass unchanged.

Not covered by tests: the paid registration flow end to end. It spends real
USDC through Dextopus and needs exercising on the preview against a real
wallet — including a reload mid-payment, which is what the persisted request id
